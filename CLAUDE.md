# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

A client-side Blu-ray (BDMV) player for desktop and mobile browsers (Safari, Chrome, Firefox; touch, installable and offline): a TypeScript port of libbluray (not WASM), its own M2TS demuxer, and WebCodecs decoding. Nothing is uploaded. The design spec is `docs/superpowers/specs/2026-10-12-bluray-web-player-design.md`. Milestones 1–4 are done: parsers, demux, H.264/HEVC video, clock, seek/chapters, basic UI, audio (LPCM, AC-3/E-AC-3, the AC-3 core of TrueHD, the DTS core of DTS/DTS-HD, with track switching), HDMV menus (VM, IG menus, UO masks, keyboard/mouse/remote input, menu sounds; spec `docs/superpowers/specs/2026-10-14-m3-hdmv-menus-design.md`), subtitles: disc PGS with forced captions and user SRT files (spec `docs/superpowers/specs/2026-10-15-m4a-pgs-srt-design.md`), and the native ASS renderer with fonts and episode subtitle sets (M4b, spec `docs/superpowers/specs/2026-10-15-m4b-ass-renderer-design.md`). Video shaders (mpv user shaders such as Anime4K on WebGL2) are also in: spec `docs/superpowers/specs/2026-10-15-video-shaders-design.md`. Milestone 5b, the BD-J JVM core, is done (spec `docs/superpowers/specs/2026-10-15-m5b-bdj-jvm-core-design.md`): it boots libbluray's Java stack in a TypeScript JVM. 5c is done too (spec `docs/superpowers/specs/2026-10-16-m5c-bdj-playback-design.md`): BD-J titles drive playback, and BD-J discs no longer open to the title picker. 5d (graphics, keys, fonts) and 5e (storage, network, speed) are next. Cross-browser and mobile support (step 1 of `docs/superpowers/specs/2026-10-16-cross-browser-and-remote-design.md`, §3) is in too. `docs/known-issues.md` lists decisions left open on purpose and resolved items. Read it before changing something it covers.

## Commands

- `npm run dev`: Vite dev server, served with COOP/COEP headers.
- `npm run typecheck` (`tsc -b`) and `npm run build` (typecheck, then `vite build`).
- `npm test`: Vitest, all unit tests (`src/**/*.test.ts` plus `tests/local/**`). Run one file with `npx vitest run src/engine/demux/ts-packet.test.ts` and filter by name with `-t "<name>"`.
- `npm run test:e2e`: Playwright against a production build on port 4173 (`npm run build && npm run preview`). Locally Playwright reuses a preview server already running on :4173 (`reuseExistingServer`), so stop a stale one after changing source. The `chromium` and `mobile-chromium` projects need installed Google Chrome (`channel: 'chrome'`) and a working audio output, because the A/V sync tests measure the real AudioWorklet clock. Run one test with `npx playwright test playback -g "<title>"`.
  - Pick a disc folder with `setFolder` (`tests/e2e/support.ts`), never `setInputFiles(folder)` or `FileChooser.setFiles(folder)`: in Playwright 1.64 those can miss the input's event in Firefox and hang until the test times out.
  - Projects: `chromium`, `firefox`, `webkit` and `mobile-chromium` (the last runs only `tests/e2e/mobile-*.spec.ts`). Run one with `npx playwright test --project=webkit`. Chrome-only specs skip elsewhere with a reason, and `skipWithoutH264` (`tests/e2e/support.ts`) skips H.264 playback where the browser can't decode it, and skips tests that need real-time playback in WebKit on Linux (CI), where it can't keep up; they still run in WebKit on macOS, and real Safari is covered by the device test. CI runs each project on its own runner. Install the others with `npx playwright install firefox webkit`.
  - `SYNC_TOLERANCE_SCALE=2` widens the 20 ms mean / 50 ms max A/V offset bounds. CI uses 1.5. Keep local runs at the default.
  - `ASS_BUDGET_SCALE=8` widens the share of animated ASS draws allowed over the renderer's 8 ms budget from 5% to 40% (`ass-subtitles.spec.ts`). CI uses 8 because its runners miss the budget on 26–29% of draws. Keep local runs at the default.
  - `npx playwright test shaders.spec` runs the shader E2E tests; `SHADERS_GPU=1` adds the Anime4K and A/V sync ones (WebGL2 with float targets; they skip with a reason when it is missing).
  - `LOCAL_DISCS=1 npx playwright test local-discs` plays every disc under `fixtures/local/` and seeks around in it. It also checks the BD-J discs there, including a 5 s warm start-up check on A_NEW_ERA.
  - Nightly drift test: `npx tsx scripts/make-fixture-disc.ts fixtures/local/long-disc --seconds-per-clip 300`, then `NIGHTLY=1 npx playwright test -g "ten minutes"`.
- `npm run fixture:synthetic`: regenerates the committed discs in `fixtures/synthetic/` from `scripts/` (the scripts build on `tests/helpers/`). Rerun it after changing the builders or muxer, and commit the output. It needs `ffmpeg` with libx264 on PATH for the video fixtures (disc1, disc-menu, disc-subs, disc-bdj, disc-bdj-mixed) and the audio fixtures (disc3), and Docker for `disc1.iso` (`scripts/make-iso-fixture.sh`).
- `npm run wasm:build`: rebuilds `src/wasm/audio/audio.wasm` in Docker (pinned emsdk). CI (`.github/workflows/wasm.yml`) rebuilds it and fails on any diff.
- `npm run vm-trace:build` / `vm-trace:golden` / `vm-trace -- <disc> <script> [--dump-pages]`: the libbluray trace harness (`tools/vm-trace/`, Docker; `<disc>` may be a path such as `fixtures/local/<name>`, `<script>` a `.keys` path). `tests/vm-trace/` compares our HDMV VM and Navigator against golden traces from patched libbluray; `vm-trace:golden` regenerates the golden files (never edit them by hand) and CI fails on any diff (`.github/workflows/vm-trace.yml`).
- `npm run test:ass`: Playwright (`playwright.ass.config.ts`, Vite dev server on port 5174) compares our ASS renderer's layout trace and pixels with the committed libass goldens for every `fixtures/ass/<name>/`. `npm run ass-trace:build` / `ass-trace:golden` / `ass-trace -- <file.ass> <fonts dir> <times file>`: the libass trace harness (`tools/ass-trace/`, Docker, libass 0.17.5); `ass-trace:golden` regenerates `tests/ass-trace/golden/` (never edit by hand; CI fails on any diff, `.github/workflows/ass-trace.yml`). `ASS_LOCAL=1 npx playwright test -c playwright.ass.config.ts local` runs the developer's real scripts in `fixtures/local/ass/<name>/` against libass live (see `tools/ass-trace/README.md`).
- `npm run bdj-trace:build` / `bdj-trace:golden` / `bdj-trace -- <disc> [--until <call>[#n]]`: the libbluray BD-J trace harness (`tools/bdj-trace/`, Docker). `tests/bdj/` compares our JVM's control-call traces with the golden ones, and `tests/bdj/replay-player.ts` replays a trace through the real `Player`; `bdj-trace:golden` regenerates them (never edit by hand; CI fails on any diff, `.github/workflows/bdj-trace.yml`). `npm run bdj-classlib:build` / `bdj-classlib:collect`: build and collect the class library in `src/bdj-classlib/` (`tools/bdj-classlib/`, Docker; CI `bdj-classlib.yml` rebuilds it and diffs).
- Probe page: `probe.html` (`src/probe/`) is a device go/no-go check: open it on a device, pick a disc folder, and it reports sample rate, `audioSession`, worker rAF, HEVC, WebGL2 float targets, `ctx.filter`, `letterSpacing`, fullscreen, `webkitdirectory`, Blob slicing over 4 GiB and `relative-path`. It is excluded from the service worker. Preview deploys use `.github/workflows/preview.yml` (once PR #3 is on main): `gh workflow run preview.yml --ref <branch>`.
- `npx tsx scripts/make-icons.ts` renders `public/favicon.svg` to the PNG app icons in `public/icons/` (commit the output).
- CI (`.github/workflows/ci.yml`) runs Node 24 and needs npm ≥ 11.19 because `package.json` uses `allowScripts`. `scripts/ci-audio.sh` sets up a PulseAudio null sink for the sync tests.

## Architecture

There are three execution contexts, and a fourth (the BD-J worker, below) while a BD-J title runs. They communicate only through typed messages and one shared buffer.

1. **Main thread** (`src/ui/`, `src/player/`): React UI. `PlayerController` is an external store over the worker protocol, read with `useSyncExternalStore`. There is no state library. `reduceEvent` is a pure reducer from `EngineEvent` to `PlayerSnapshot`, and it is unit-tested. `create-controller.ts` starts the worker. `?telemetry=1` copies telemetry to `window.__blurayTelemetry`, which is what the E2E tests read (its `bdj` field holds BD-J start-up times since the open). `?bdjfail=1` is test-only: the engine worker gets an unreadable class library, so BD-J fallback can be tested in the browser.
2. **Engine worker** (`src/engine/`, framework-free, entry point `worker.ts`): `Player` owns one disc and at most one playing playlist (a `Session`). The `<canvas>` is transferred as an `OffscreenCanvas`, so presentation timing doesn't depend on React.
3. **AudioWorklet** (`src/player/pcm-worklet.ts`): plays PCM from a `SharedArrayBuffer` ring (`engine/audio/ring.ts`) and atomically publishes the count of frames played. `MasterClock` derives playback time from that count, falling back to the wall clock when no audio is playable. Video frames are presented against this clock.

`src/engine/protocol.ts` is the contract between the UI and the engine. It defines the `EngineCommand` and `EngineEvent` discriminated unions and `Telemetry`. Change it first when you add a feature that crosses the boundary.

Data flow inside the engine:
- `disc/`: `ByteSource` and `FileSource` (a normalized `path → Blob` map, so the engine never sees file handles). `open-disc.ts` loads index, playlists and clips and maps failures to `DiscError` codes. `ByteSource.read` takes an `AbortSignal`.
- `bdmv/`: `index.bdmv`, `.mpls` and `.clpi` parsers, ported from libbluray.
- `nav/timeline.ts`: maps play items onto one continuous playlist time, handling the 33-bit PTS wrap and per-item discontinuities. Seeks go through the EP map to an SPN, then to an aligned byte offset.
- `demux/` (192-byte source packets, then TS, then PES) feeds `playback/pipeline.ts`, which runs read-ahead, backpressure and cancellation of abandoned reads on a seek.
- `decode/`: `WebCodecsVideoDecoder` (Annex-B; the codec string comes from the SPS in `h264.ts`/`hevc.ts`) and `lpcm.ts`. Audio goes PES → `AudioFramer` (`audio-frames.ts`) → `WasmFrameDecoder` (`wasm-audio.ts`, or LPCM) → `PcmChunk` → `AudioWriter`; decoders come from `PlayerDeps.createAudioDecoder`, and TrueHD is reduced to its AC-3 core by `TrueHdCoreFilter` first. `render/`: `VideoPresenter` (chooses which frame to show against the clock) and `Compositor`.

Subtitles: `nav/subtitles.ts` (`PgStreamControl`) follows PSR2 on the navigator's registers (or private ones on discs without a navigator), decodes the PG PID the pipeline reads (`graphics/pg-decoder.ts`) and renders display sets at their PTS into a double-buffered PG `OverlayPlane` (`graphics/pg-renderer.ts`); SRT is decoded, parsed and laid out by original code in `subs/`; the compositor draws video, PG, text, then IG.

ASS (`ass/`): ported from libass 0.17.5 function by function: `parse.ts` (script and `[Fonts]`), `fonts.ts`/`font-tables.ts` (matching from the sfnt tables, faces registered as `FontFace`s), `tags.ts`/`state.ts`/`events.ts` (override tags and `\t`), `layout.ts` (advances from the browser's `measureText` through `GlyphMeasurer`, wrapping, alignment), `transform.ts`, `collisions.ts`, `frame.ts` (one frame's events and matrices); `raster.ts` draws runs with Canvas2D (glyph masks supersampled and box-filtered in JS, libass's compositing and blur, mask and layer LRUs) and `renderer.ts` (`AssRenderer`, a `TextRendererLike`) caches static events. `tests/ass-trace/` compares it with patched libass; a divergence is a porting bug, as with vm-trace. `subs/text-set.ts` holds the episode subtitle set: several SRT/ASS files, each placed at a playlist time (auto-placed on play items of 5 minutes or more) with its own offset.

Menus: `nav/navigator.ts` owns the HDMV VM (`hdmv/`), the register file and the graphics controller (`graphics/`) and drives the `Player` through a narrow `PlaybackPort`; IG units are queued by PTS (sub-path IG is preloaded whole) and the controller's overlay operations update an `OverlayPlane` that the compositor draws over the video. All of it is ported function by function from libbluray at commit `448f896` (`scripts/fetch-libbluray.sh` puts the source in `.cache/libbluray`); `tests/vm-trace/` compares our VM, navigator and graphics against patched libbluray traces, and a divergence is a porting bug to fix in the port, never in a golden file.

Shaders: `shaders/` in the engine parses mpv user shaders (`parse.ts`, `rpn.ts`), plans a frame's passes (`plan.ts`) and runs them on WebGL2 in the worker (`webgl-backend.ts`); `ShaderStage` (driven by the `setVideoShaders` command and `shaderStatus` event) sits between the decoder and the compositor, so the shader output replaces the video frame. The UI side is `ui/shader-sets.ts` (the 12 built-in Anime4K sets and `input.conf` imports), `ui/shader-library.ts` (IndexedDB), `ui/shader-model.ts` and the Shaders menu, and `v` cycles sets. Anime4K is vendored in `fixtures/shaders/`.

BD-J (`src/engine/bdj/`, milestone 5b): a JVM in TypeScript that runs libbluray's Java stack. `jvm/` holds the class-file parser, zip reader, loader, heap, interpreter, green threads (`threads`), the virtual file system (`vfs`) and `natives/`; `host.ts` has the `BdjHost` interface and `RecordingHost`; `runtime.ts` (`BdjRuntime`) is ported from libbluray's `bdj.c`. `tests/bdj/conformance` runs small Java programs and compares their output with HotSpot's; `tests/bdj/` also holds the control-call trace comparison and the synthetic BD-J disc.

BD-J playback (`src/engine/bdj/`, milestone 5c) adds a fourth execution context, the BD-J worker (`bdj-worker.ts`, entry `bdj-worker-entry.ts`), started by the engine worker once per BD-J entry. The register file is shared with it through a `SharedArrayBuffer` (`shared-registers.ts`), and a status block (`status-block.ts`) carries playback time and the UO mask. `BdjSession` (engine side) routes Java's calls to `PlayerBdjHost` (`player-host.ts`), which drives the `Player`; playback PSR updates are shared with the Navigator (`nav/playback-psrs.ts`); events for Java come from `events.ts`. The HDMV Navigator is dropped while BD-J runs. `PlayerDeps` gains `createBdjWorker`, `loadClassLibrary`, `setTimer`, `playerSettings` and `bdjLog`. A failed boot falls back to the title picker at once; only a hang waits for the 20 s timer that runs from the boot to Java's first `selectPlaylist`. Telemetry has `bdj { bootMs, firstPlaylistMs, firstFrameMs }`. Graphics, keys and fonts are not handled yet (5d).

Cross-browser: `src/ui/capabilities.ts` builds the capability report that gates features per browser (no user-agent sniffing, except the iPadOS check below). The memory profile (`src/engine/memory-profile.ts`, chosen by `src/ui/memory-profile.ts`, forced with `?memory=desktop|constrained`) reaches the engine as the `setMemoryProfile` command and sets the IG sub-path preload limit, the ASS cache budgets and text supersampling cap, and the decoded-frame queue length; the constrained profile skips IG sub-paths over 64 MB. `src/player/platform-session.ts` holds Wake Lock and Media Session, `src/ui/touch.ts` the touch gestures, and a fullscreen adapter (with an Add-to-Home-Screen hint on iPhone) replaces element fullscreen where it is missing. The service worker is `src/sw.ts` (vite-plugin-pwa `injectManifest`, `tsconfig.sw.json`): production-only registration, COOP/COEP re-added to cached responses, network-first navigation with a 3 s timeout, `probe.html` excluded.

Testability pattern: `Player` takes its side effects through `PlayerDeps`: `emit`, `videoCodecApi`, `nowMs`, `requestFrame` and `createCompositor`. `PlayerController` takes a `WorkerLike` and an `AudioOutputLike`. Unit tests inject fakes, for example a fake `VideoDecoder` that can deliver output late. Keep new browser APIs behind injectable interfaces like these.

## Constraints

- **Licensing:** `src/engine/` is LGPL-2.1 and keeps its own `LICENSE` and `NOTICE`. It must not import React or anything from `src/ui/` or `src/player/`. When you port or derive code from libbluray, libass (ISC) or FFmpeg, record the source file in `src/engine/NOTICE`.
- **`src/wasm/` is LGPL** (FFmpeg-derived decoders plus `shim.c`). `src/wasm/audio/audio.wasm` is committed and must only be rebuilt with `npm run wasm:build`, never by hand, so CI's diff check stays valid.
- **`src/bdj-classlib/` is GPLv2 with the Classpath Exception** (OpenJDK-derived classes) plus LGPL libbluray jars. It is committed and must only be rebuilt with `npm run bdj-classlib:build`, so CI's diff check stays valid. DoppioJVM (MIT) and fdlibm attributions are in `src/engine/NOTICE`. Never copy HotSpot, GNU Classpath or JamVM code into the JVM. `src/bdj-classlib/intrinsics/` holds OpenJDK-derived TypeScript intrinsics under the same GPLv2+Classpath Exception; they are injected through `JvmOptions.extraIntrinsics`, and `src/engine` imports them only from the BD-J worker entry.
- **Supported browsers:** Safari 26 (macOS, iOS, iPadOS), Chrome and Firefox desktop at stable and stable−2, Chrome Android. Firefox Android is unsupported. Don't add user-agent sniffing; one exception is the iPadOS check (`navigator.platform === 'MacIntel'` with touch points) in `src/ui/memory-profile.ts`, because iPadOS reports a Mac. The other is `defaultDeviceName` in `src/ui/nas/nas-client.ts`, which reads the user agent only to suggest the editable device name for NAS pairing and gates no feature.
- **Cross-origin isolation is required** for `SharedArrayBuffer`. The Vite dev and preview servers set COOP/COEP in `vite.config.ts`. Static deploys rely on `public/_headers`. Don't add resources that would break `require-corp`.
- **Test fixtures:** `fixtures/synthetic/` is committed and generated by the scripts. `fixtures/shaders/` (vendored Anime4K files and basic test shaders) is committed. `fixtures/ass/` (hand-written ASS scripts and open-licence fonts) is committed; its goldens come from `ass-trace:golden`. `fixtures/local/ass/<name>/` holds the developer's real scripts and fonts (gitignored). `fixtures/local/<name>/BDMV/...` holds the developer's own decrypted discs and is gitignored. `tests/local` and `local-discs.spec.ts` skip when it is absent. Blu-ray clips often exceed 4 GiB, so `tests/local` reads ranges through its own Blob stand-in, because Node's `openAsBlob` reports sizes modulo 2^32.
- TypeScript is strict, with `noUnusedLocals`/`noUnusedParameters` and `verbatimModuleSyntax` (use `import type` for type-only imports). `tsconfig.app.json` also typechecks `tests/helpers`.
